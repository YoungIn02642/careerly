# 배포 — Railway

careerly 를 Railway 에 올리는 절차. 처음 한 번은 이 문서를 위에서 아래로 따라가면 된다.

> **왜 Railway 인가** — careerly 는 `db.json` 파일 하나에 회원·스펙·결제 내역을 담는다.
> 배포 플랫폼의 파일시스템은 휘발성이라 재배포·재시작마다 그 파일이 사라진다.
> Railway 는 **볼륨(영속 디스크)** 을 붙일 수 있어 지금 코드를 한 줄도 안 고치고
> 데이터를 유지할 수 있다. Render 무료 티어에는 볼륨이 없어 회원이 계속 날아간다.

```bash
for f in test/*.test.js; do node "$f" | tail -1; done   # 전부 통과해야 한다
git status --porcelain                                   # 비어 있어야 한다
```

---

## 2. Railway 프로젝트 만들기

1. [railway.app](https://railway.app) → **New Project → Deploy from GitHub repo** → `careerly`
2. 배포가 한 번 실패하거나 이상하게 잡히면 **Settings** 에서 다음을 지정한다.

| 항목 | 값 | 이유 |
|---|---|---|
| **Root Directory** | `backend` | `package.json` 이 저장소 루트가 아니라 `backend/` 에 있다 |
| **Start Command** | `npm start` | (기본값. 명시해 두면 안전하다) |

Node 버전은 `backend/package.json` 의 `engines` 에서 읽는다(`>=20`).

---

## 3. 볼륨 붙이기 ← **이걸 빼먹으면 회원이 계속 사라진다**

**Settings → Volumes → New Volume**

| 항목 | 값 |
|---|---|
| **Mount Path** | `/data` |

> ### ⚠️ `backend/data` 에 마운트하지 말 것
> 그 폴더에는 커밋된 캐시가 8개 들어 있다 — `wage-jobs.json`(직업 분류·연봉),
> `qnet-certs.json`(자격증 613종), `ftc-large-groups.json`·`public-orgs.json`·
> `local-public-orgs.json`·`work24-companies.json`(기업 분류), `ncs-taxonomy.json`,
> `career-data.json`.
> 볼륨을 여기 걸면 **그 파일들이 전부 가려져서** 커리어 로드맵·자격증 검색·기업 분류가
> 조용히 죽는다. 화면에는 에러가 아니라 "데이터 없음" 으로 나와 원인을 찾기 어렵다.
>
> 빈 경로(`/data`)에 마운트하고, 아래 `CAREERLY_DB_PATH` 로 **db.json 만** 그쪽을 보게 한다.

---

## 4. 환경변수

**Variables** 에 넣는다. 로컬 `.env` 를 그대로 복사하되 아래 네 개를 **추가·수정**한다.

| 변수 | 값 | 설명 |
|---|---|---|
| `CAREERLY_DB_PATH` | `/data/db.json` | 볼륨에 저장 (3번과 짝) |
| `NODE_ENV` | `production` | 쿠키 secure, 백오피스 404 |
| `ALLOWED_ORIGINS` | `https://<배포도메인>` | CORS 허용 도메인 |
| `OAUTH_REDIRECT_BASE` | `https://<배포도메인>` | 소셜 로그인 콜백 주소 |

그대로 옮길 것: `DATA_GO_KR_SERVICE_KEY` · `GROQ_API_KEY` · `CAS_AI_PROVIDER` ·
`NAVER_CLIENT_ID/SECRET`(뉴스) · `NAVER_LOGIN_CLIENT_ID/SECRET` ·
`KAKAO_REST_API_KEY` · `KAKAO_CLIENT_SECRET` · `TOSS_CLIENT_KEY` · `TOSS_SECRET_KEY`

`PORT` 는 **넣지 않는다** — Railway 가 주입한다.

## 5. 도메인 받고 콘솔에 등록

배포되면 **Settings → Networking → Generate Domain** 으로 주소가 나온다
(`careerly-production-xxxx.up.railway.app`).

그 주소를 4번의 `ALLOWED_ORIGINS`·`OAUTH_REDIRECT_BASE` 에 채우고 **재배포**한 뒤,
각 콘솔에 콜백을 **추가** 등록한다. 로컬 주소는 지우지 말 것 — 개발할 때 계속 쓴다.

| 서비스 | 등록할 곳 | 값 |
|---|---|---|
| 네이버 | 애플리케이션 → API 설정 → 서비스 환경 | 서비스 URL `https://<도메인>`<br>Callback `https://<도메인>/api/auth/naver/callback` |
| 카카오 | 앱 설정 → 플랫폼 → Web | 사이트 도메인 `https://<도메인>` |
| 카카오 | 앱 설정 → 플랫폼 키 → **REST API 키** | 리다이렉트 URI `https://<도메인>/api/auth/kakao/callback` |

> 카카오는 로그인 **전에는** 리다이렉트 URI 를 검사하지 않는다. 등록이 틀려도 로그인
> 화면까지는 뜨고, 로그인한 뒤에야 `KOE006` 이 난다. 반드시 실제로 로그인해 봐야 안다.

## 6. 배포 후 확인

```bash
curl https://<도메인>/api/health                 # {"ok":true}
curl https://<도메인>/api/auth/providers         # 네이버·카카오 둘 다 나오는지
curl https://<도메인>/api/payments/config        # {"enabled":true, clientKey:"test_ck_..."}
curl -s https://<도메인>/api/jobs | head -c 120  # 직업 분류가 살아있는지 (볼륨 사고 확인)
curl -s -o /dev/null -w "%{http_code}\n" https://<도메인>/api/admin/users   # 404 여야 정상
```

브라우저에서:
1. 네이버·카카오 로그인 → **추가입력 화면**이 뜨는지
2. 멘토 찾기 → 신청 → **결제창**이 뜨는지 (테스트 키라 돈은 안 나간다)
3. **재배포한 뒤 다시 로그인** → 계정이 살아있는지 ← **볼륨이 제대로 붙었는지 확인하는 유일한 방법**

---

## 7. 첫 배포 후: 통계 표본 채우기

빈 DB 로 시작하므로 커리어 로드맵·CAS 화면이 전부 "데이터 없음" 이다.
운영에서는 백오피스가 404 로 막혀 있어 화면으로는 시드를 넣을 수 없다.

표본이 필요하면 `NODE_ENV` 를 잠시 비우고 배포 → 백오피스에서 **데모 데이터 시드** →
다시 `production` 으로 되돌린다. (운영에 개발용 라우트를 열어두는 것이므로 **반드시**
되돌릴 것.)

## 알려진 것들

- **SQLite 는 죽은 경로다.** `routes/careerData.js` 만 쓰고 프론트는 호출하지 않는다.
  `careerly.db` 는 gitignore 대상이라 배포 환경엔 없지만, sqlite3 가 파일을 새로 만들어
  서버가 죽지는 않는다(빈 결과가 나올 뿐). 정리하려면 그 라우트와 `sqlite3` 의존성을
  같이 걷어내면 되고, 그러면 네이티브 빌드가 사라져 배포도 빨라진다.
- **결제는 테스트 키다.** 실결제로 바꾸려면 토스 계약 후 `live_` 키로 교체한다.
  그전까지는 실제 돈이 오가지 않는다.
- **세션은 db.json 에 있다.** 재배포하면 세션이 유지되므로 로그인이 풀리지 않는다
  (볼륨을 붙였을 때).
