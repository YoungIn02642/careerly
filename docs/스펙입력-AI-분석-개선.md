# 스펙 입력 · AI 한 번에 입력 개선 (2026-07-27)

스펙 입력 페이지의 **정성 스펙 · 대표 활동 → AI로 한 번에 입력** 기능이
`Failed to fetch` 로 죽고, 동작하더라도 결과가 엉망이던 문제를 고치고,
그 과정에서 드러난 CAS 배점 서열 문제까지 함께 정리한 기록.

관련 파일: `backend/src/routes/casAnalyze.js` · `backend/src/spec-parse.js`(신규)
· `frontend/js/spec-form.js` · `frontend/js/cas.js` · `test/cas.test.js`

---

## 1. `Failed to fetch` 의 원인

브라우저가 서버에 **아예 닿지 못했을 때** 나오는 메시지다. 두 가지가 겹쳐 있었다.

| 원인 | 증상 | 조치 |
|---|---|---|
| 백엔드 미실행 / `file://` 로 HTML 직접 열기 | `Failed to fetch` 원문 노출 | 안내 문구로 치환 (아래) |
| `qwen3:8b` 미설치 (설치된 건 `mistral`, `llama3.1`) | Ollama 404 → 503 | 설치된 모델 중 자동 선택 |

`OLLAMA_MODEL` 이 없으면 `/api/tags` 를 조회해 같은 계열 → 선호 순위(`qwen3` >
`qwen2.5` > `llama3.1` > …) → 아무거나 순으로 **자동 대체**한다. `ollama pull` 을
강요하지 않는다.

프론트에서는 `Failed to fetch` / `NetworkError` / `Load failed` 를 감지해
이렇게 바꿔 보여준다:

> 백엔드 서버에 연결하지 못했어요. `cd backend && npm start` 로 서버를 켠 뒤,
> HTML 파일을 직접 여는 대신 http://localhost:3000 으로 접속해 주세요.

## 2. 진짜 문제 — AI 단독으로는 못 쓸 수준

`llama3.1:8b` 에 세 줄을 넣은 결과:

```
입력: 국민은행 인턴쉽 3개월 / 2026년 AI챔피언 해커톤 대회 우수상 / 학부연구생 1년
출력: 3건 전부 type='other', name='' — 3분 51초 소요
```

그래서 **규칙 파서를 1차로 두고 AI 는 보조로** 돌리는 구조로 바꿨다(`spec-parse.js`).

```
텍스트 ─┬─ 규칙 파서가 읽은 줄 ────────────────────→ 그대로 사용
        └─ 못 읽은 줄만 ─→ 웹 검색(기간) ─→ AI 분류 ─→ 병합
```

- 한국어 스펙 표기는 어휘가 좁아 규칙으로 대부분 정확히 잡힌다.
- **Ollama 가 꺼져 있어도 기능이 동작한다.** AI 가 실패해도 규칙 결과는 반환하고
  `notice` 로 알린다(규칙도 아무것도 못 읽었을 때만 진짜 오류).
- 점수는 어차피 서버가 `cas.js` 로 다시 매기므로 모델에게 채점을 시키지 않는다.

### 결과

| 입력 | 이전 | 이후 |
|---|---|---|
| 사용자 입력 3줄 | 3분 51초 · 전부 `other` | **1.1초** · 전부 정확 |
| 규칙에 없는 표기 포함 | 120초 | **38초** |

## 3. 빈칸을 채우는 규칙 (사용자 결정)

| 항목 | 미기입 시 |
|---|---|
| 기간 | ① 웹 검색(DuckDuckGo)으로 활동을 찾아 추정 → ② 실패 시 통상 기간 |
| 역할 | `팀원` 고정 (연구 유형은 `학부연구생`, 동아리는 `동아리원, 일반학회원`) |
| 성과 | `결과물 없음` 고정. 단 "우수상" 등이 있으면 `수상` |

**웹 검색 기간 추정은 보수적으로 간다.** 검색 결과에는 "2026년", "10년 전통" 같은
기간이 아닌 숫자가 널려 있어서, 처음엔 해커톤이 `1년이상` 으로 잡혔다. 그래서
(1) `기간·동안·진행·근무` 같은 문맥 단어 옆 숫자만 보고, (2) 여러 스니펫에서
2회 이상 겹칠 때만 채택한다. 못 정하면 통상 기간표로 넘어간다.

통상 기간은 유형별 기본값 위에 활동명 키워드가 우선한다
(`해커톤` → 1개월 미만, `하계/동계` → 1~3개월, `캡스톤` → 6개월~1년).

## 4. 성능

`교내활동` 이 규칙 사전에 없어 그 한 줄 때문에 120초가 걸리는 일이 있었다.

1. **사전 보강** — `교내활동·비교과·멘토링·서포터즈·부트캠프` 등 흔한 표기 흡수.
2. **분류 전용 경량 프롬프트** — AI 를 부를 때 채점 루브릭·정량 스키마를 뺀
   1/5 길이 프롬프트(`SYSTEM_CLASSIFY`)를 쓴다. CPU 추론에서는 프롬프트 길이가
   그대로 대기시간이다.
3. `num_ctx` 8192 → 2048, `num_predict` 512 상한.

## 5. 파싱에서 잡은 버그들

| 증상 | 원인 | 조치 |
|---|---|---|
| 활동명이 `삼성전자 하계인턴 1~ 팀원` | `1~3개월` 중 뒷부분만 지워 `1~` 잔여 | 범위 표기를 통째로 제거 + 역할·성과 단어 제거 |
| 동아리 역할 칸이 빈칸 | `exec` 유형 선택지는 `임원진 / 동아리원, 일반학회원` 뿐인데 `팀원` 을 내려보냄 | `normalizeRole()` 로 유형별 허용값에 맞춰 변환 |
| `6개월` 이 `6개월~1년` 으로 | 경계 처리 | 위쪽 포함(`3개월` → `1~3개월`) |
| `토익 920 …` 줄이 가짜 활동으로 | 정량 전용 줄을 AI 에 넘김 | 정량으로 읽힌 줄은 활동 후보에서 제외 |
| 토스 `Lv6` 가 폼에 안 들어감 | 폼은 `NL~AL` 등급 셀렉트 | 레벨 → 등급 환산 |

## 6. CAS 배점 개편

### 6-1. 문제

- 대외활동 74점이 공모전(78) 바로 아래 — 교내 프로그램 1건이 동아리 회장 1년과 동점.
- 인턴십이 회사 규모와 무관하게 동일 배점 — 삼성전자 인턴 = 소규모 인턴.
- **동아리(46) > 교환학생(40)** 으로 의도한 서열과 반대.
- 석사(90)·박사(102)가 대기업 인턴 3개월(96)에도 못 미침.

### 6-2. 확정안 (A안 — 순서 정렬)

합의 서열: **인턴십 > 공모전 ≥ 대외활동 > 교내활동 > 어학연수 > 동아리·봉사**
(프로젝트는 실무 역량을 직접 증명하므로 대외활동 위)

| 유형 | 이전 | 이후 |
|---|---|---|
| 인턴십 | 100 | 100 |
| 공모전·대회 | 78 | 78 |
| 프로젝트 | 62 | 62 |
| 학부연구생·석사·박사 | 58 | 58 |
| 대외활동 | 74 | **58** |
| 교내활동·비교과 | (없음) | **44** (신설) |
| 교환학생·어학연수 | 40 | 40 |
| 동아리·학회 | 46 | **34** |
| 봉사활동 | 30 | 30 |

**연구 단계 배수** `1.0 / 1.15 / 1.3` → **`1.0 / 1.6 / 2.2`**

**기업 규모 배수(인턴십 전용)** 신설 — 대기업·공공기관 ×1.2 / 중견 ×1.1 / 중소·미상 ×1.0

### 6-3. 적용 후 점수

| 활동 | 점수 |
|---|---|
| 대기업 인턴 1년 | 162 |
| **박사** | **172** |
| **석사** | **125** |
| 대기업 인턴 3~6개월 | 120 |
| 공모전 수상 1~3개월 | 81 |
| 학부연구생 1년 | 78 |
| 프로젝트 6개월 깃헙 | 71 |
| 대외활동 6개월 | 58 |
| 동아리 회장 1년 | 55 |
| 교환학생 1년 | 54 |
| 교내활동 6개월 | 44 |
| 봉사 1년 | 41 |

기준점: 석사 ≈ 대기업 인턴 3~6개월, 박사 > 대기업 인턴 1년.

### 6-4. 기업 규모 판정

`company-classify` 를 재사용해 활동명에서 회사를 찾는다. "삼성전자 하계인턴" 처럼
수식어가 붙으므로 어절을 앞에서부터 잘라가며 등록된 회사명을 찾는다.

판정 결과(`companyTier`)는 **스펙에 함께 저장된다**. 저장하지 않으면 재계산 때
배수가 사라져 "입력할 때 본 점수"와 "저장 후 점수"가 어긋난다.
폼에는 `🏢 삼성전자 — 대기업으로 확인되어 점수 ×1.2 적용됐어요` 로 근거를 보여준다.

## 7. 남은 사항

- **동아리 회장 1년(55) > 교환학생 1년(54)** — 기본배점은 34 < 40 이지만 임원진 ×1.2 와
  1년 ×1.35 가 겹쳐 역전된다. 어떤 조건에서도 서열을 지키려면 동아리를 28 로 내려야 한다.
- **`공모전 ≥ 대외활동`** 이라 했으나 실제로는 78 vs 58 로 20점 차. 더 붙이려면 대외활동 68 정도.
- **레이더 차트·비교표에 교내활동이 안 보인다.** `cas-radar.js` 와 `cas-compare.js` 는
  인턴십·공모전·대외활동·프로젝트만 축으로 쓴다(동아리·교환학생·연구도 원래부터 제외).
  총점에는 정상 반영된다.
- **기업 규모 사전에 국민은행이 없어 `중소기업`(×1.0)으로 잡힌다.** 판정 실패가
  감점은 아니지만 대기업 가산도 못 받는다. 사전 보강이 필요하다.
- 대외활동 74 → 58 변경은 **이미 저장된 회원들의 정성 점수도 낮춘다.**
  반대로 기존 데이터에는 `companyTier` 가 없어 인턴 가산은 붙지 않는다(다시 저장하면 붙는다).

## 8. 검증 방법

브라우저 확장을 쓸 수 없어, **실제 `spec-form.js` 를 jsdom 에 올리고 실제 백엔드에
붙여** 버튼 클릭 → select 값 읽기 → 저장 payload 가로채기까지 같은 경로로 확인했다.
저장 후 재계산 점수가 화면 점수와 일치하는 것까지 봤다.

```bash
node test/cas.test.js      # 47개 통과
```

테스트에 이번 규칙을 추가했다 — 유형 서열 내림차순, 교내활동 > 어학연수 > 동아리,
석사 ≈ 대기업 인턴 3~6개월(±15%), 박사 > 대기업 인턴 1년, 기업규모 배수(미상이면
중소와 동일 = 옛 데이터 점수 불변, 인턴십에만 적용).
