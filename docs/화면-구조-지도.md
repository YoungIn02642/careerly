# 화면 구조 지도 — 무엇을 어디서 고치나

careerly 프론트엔드는 **빌드 없는 단일 문서 SPA** 다. HTML 파일이 하나뿐이라
"이 화면 HTML은 어디 있지?"를 찾는 데 시간을 쓰기 쉽다. 그 지도를 여기 둔다.

> **행 번호는 참고용이다.** 코드를 고치면 밀린다. 정확히 찾으려면 아래
> [찾는 요령](#찾는-요령)의 `grep` 을 쓰고, 행 번호는 "대충 이 근처" 정도로만 본다.

---

## 1. 큰 그림

```
frontend/careerly.html      ← 화면 HTML 전부 (866줄, 페이지 11개가 이 안에)
frontend/css/*.css          ← 4개 파일
frontend/js/*.js            ← 15개 모듈
backend/src/server.js       ← API + 정적 파일 서빙
```

**동작 방식** — `careerly.html` 안에 `<div class="page" id="page-XXX">` 가 11개 들어 있고,
`js/app.js` 의 `showPage()` 가 그중 하나에만 `.active` 를 붙인다. 나머지는 CSS 로 숨는다.
주소는 해시 라우팅(`#career`, `#jd` …). **페이지를 이동해도 문서는 다시 로드되지 않는다.**

## 2. 페이지 지도

| 주소 | 화면 이름 | HTML 위치 | 내용을 만드는 곳 |
|---|---|---|---|
| `#main` | 홈 | `careerly.html` **112행** | HTML + `js/home.js` (일부 섹션) |
| `#login` | 로그인 | **335행** | HTML |
| `#signup` | 회원가입 | **363행** | HTML |
| `#mypage` | 스펙 입력 | **438행** | ⚠️ **`js/spec-form.js`** |
| `#backoffice` | 백오피스(개발용) | **452행** | ⚠️ **`js/backoffice.js`** |
| `#dashboard` | 멘토링 대시보드 | **458행** | HTML + `js/mentoring.js` |
| `#search` | 멘토 찾기 | **554행** | HTML + `js/mentoring.js` (카드) |
| `#profile` | 멘토 상세 | **611행** | ⚠️ **`js/mentoring.js`** |
| `#mentoring` | 내 멘토링 | **616행** | HTML + `js/mentoring.js` (탭 내용) |
| `#jd` | 자소서 코치 | **709행** | HTML(입력부) + `js/jd-coach.js`(결과) |
| `#career` | 커리어 로드맵 | **793행** | HTML(사이드바) + `js/career.js`(본문) |

### ⚠️ HTML만 보면 안 보이는 화면

**아래 세 곳은 HTML이 빈 껍데기다.** 여기서 제일 많이 헤맨다.

| 화면 | HTML에 있는 것 | 실제 내용 |
|---|---|---|
| 스펙 입력 | `<div id="mypage-form-container"></div>` | `spec-form.js` → `render()` |
| 멘토 상세 | `<div class="wrap" id="profile-body"></div>` | `mentoring.js` → `openProfile()` |
| 백오피스 | `<div class="bo-wrap"></div>` | `backoffice.js` → `render()` |

**커리어 로드맵과 자소서 코치도 절반은 JS다.**

| 화면 | HTML에 있는 것 | JS가 채우는 것 |
|---|---|---|
| 커리어 로드맵 | 왼쪽 사이드바 껍데기 `#job-major-list` | `#career-main` — 1차/2차 분류·직업 카드·연봉·스펙 통계 (`career.js`) |
| 자소서 코치 | 입력 4분할(회사/공고/JD/문항) | `#jd-result`·`#jd-questions-result`·`#jd-news-result` (`jd-coach.js`) |

## 3. JS 모듈 — 무엇을 담당하나

로드 순서는 `careerly.html` 821~863행. **의존 순서가 있으니 임의로 바꾸지 말 것**
(`db.js` → 카탈로그 → `cas.js` → 화면 모듈 → `app.js`).

### 화면 모듈

| 파일 | 줄 | 담당 | 주로 건드리는 DOM |
|---|---|---|---|

## 4. CSS — 어느 파일에 있나

| 파일 | 줄 | 범위 |
|---|---|---|
| `main.css` | 1544 | 공통(네비·버튼·폼) + **홈 일부 + 스펙 입력 + 커리어 로드맵** |
| `mentoring.css` | 781 | 멘토 찾기·상세·내 멘토링·대시보드 |
| `jd-coach.css` | 308 | 자소서 코치 |
| `home.css` | 251 | 홈 |

로드 순서는 `main.css` → `home.css` → `mentoring.css` → `jd-coach.css`.
**뒤에 오는 파일이 이긴다.** 같은 클래스명을 두 파일에 쓰면 조용히 덮인다.

## 5. 백엔드 — API 지도

`backend/src/server.js` 가 진입점. 라우터가 붙는 곳은 다음 5개다.

| 경로 | 파일 | 역할 |
|---|---|---|
| `/api/career-data` | `routes/careerData.js` | 동문 데이터 |
| `/api/recommendations` | `routes/recommendations.js` | 추천 |
| `/api/cas` | `routes/casAnalyze.js` | 스펙 텍스트 AI 분석 |
| `/api/jd` | `routes/jdCoach.js` | 자소서 코치 역량 추출 |
| `/api/news` | `routes/news.js` | 회사 뉴스 |

`server.js` 안에 직접 있는 주요 라우트:

| 메서드 · 경로 | 하는 일 |
|---|---|
| `POST /api/auth/signup` · `login` · `logout`, `GET /api/auth/me` | 인증(세션 쿠키) |
| `GET/PUT /api/specs/me` | 내 스펙 |
| `GET /api/company/classify` | 회사명 → 기업 규모 |
| `GET /api/company/suggest` | 회사명 자동완성 |
| `GET /api/certs` | 자격증 카탈로그(국가자격+민간) |
| `GET /api/jobs` | **직업 분류 + 연봉** (커리어 로드맵) |
| `POST /api/admin/*` | 데모 시드·초기화 (**운영에선 404**) |

### 외부 데이터 캐시

화면에서 외부 API를 직접 부르지 않는다. **수집 스크립트가 JSON으로 받아 두고 서버는 그걸 읽는다.**

| 캐시 파일 | 만드는 스크립트 |
|---|---|
| `wage-jobs.json` | `scripts/fetch-wage-jobs.js` (직업 분류·연봉) |
| `qnet-certs.json` | `scripts/fetch-qnet-certs.js` (국가자격 613종) |
| `ftc-large-groups.json` | `scripts/fetch-ftc-groups.js` (대기업 판별) |
| `public-orgs.json` · `local-public-orgs.json` | `scripts/fetch-public-orgs.js` · `fetch-local-public-orgs.js` |
| `work24-companies.json` | `scripts/fetch-worknet-jobs.js` |
| `ncs-taxonomy.json` | `scripts/fetch-ncs-taxonomy.js` |

자세한 규격·함정은 `docs/외부API-연동구조.md` 참고.

## 6. 찾는 요령

### 화면에서 본 문구로 찾기 (제일 빠름)

```bash
grep -rn "찾는 문구" frontend/careerly.html frontend/js/
```

HTML에서 안 나오면 JS가 만든 것이다. 반대도 마찬가지.

### 클래스명·id 로 찾기

```bash
grep -rn "jc-wage" frontend/          # CSS·JS 어디에 있든 다 나온다
```

### 페이지 컨테이너 위치를 다시 뽑기 (행 번호가 밀렸을 때)

```bash
grep -n 'id="page-[a-z]*"' frontend/careerly.html
```

### 어떤 JS가 어떤 DOM을 채우는지

```bash
grep -n "getElementById\|querySelector" frontend/js/career.js
```

## 7. 고칠 때 알아둘 것

- **테스트는 저장소 루트에서**: `for f in test/*.test.js; do node "$f" | tail -1; done`
- **새 라우트·새 파일을 추가하면 서버를 반드시 재시작한다** (`npm run dev`)
- **프론트만 고쳤으면 새로고침으로 충분하다** (빌드 없음)
- **`file://` 로 열면 동작하지 않는다** — 데이터가 전부 서버 API 에 있다. `http://localhost:3000` 으로 접속
- **`js/ncs.js` 는 자동 생성 파일이다.** 고치려면 `backend/scripts/gen-ncs-js.js` 를 고치고 다시 생성
- **배점 상수는 `js/cas.js` 한 곳에만 둔다.** 백엔드도 여기서 읽으므로 다른 곳에 복사하지 말 것

### 자주 하는 작업 → 고칠 파일

| 하려는 것 | 고칠 곳 |
|---|---|
| 스펙 입력 항목 추가·수정 | `js/spec-form.js` + 저장 형식은 `handleSave()` |
| CAS 배점·가중치 변경 | `js/cas.js` (+ `test/cas.test.js`) |
| 커리어 로드맵 화면 | `js/career.js` + `css/main.css` |
| 자소서 코치 화면 | `js/jd-coach.js` + `css/jd-coach.css` |
| 멘토링 관련 전부 | `js/mentoring.js` + `css/mentoring.css` |
| 새 API 추가 | `backend/src/server.js` (라우트) → `frontend/js/db.js` (호출 함수) |
| 회원가입 항목 추가 | `careerly.html`(입력칸) + `js/app.js`(검증·전송) + `backend/src/server.js`(저장) |
