# 팀 개발환경 — clone 부터 첫 PR 까지

careerly 를 처음 받는 사람이 위에서 아래로 따라가는 문서. **막히는 지점이 있으면
이 문서의 구멍이니 고쳐서 커밋한다.**

전제: Node 20 이상, Docker, Git.

---

## 1. 저장소 받기

```bash
git clone https://github.com/YoungIn02642/careerly.git
cd careerly
npm install        # 루트에서 한 번. workspaces 라 backend/ 의존성까지 깔린다
```

> `cd backend && npm install` 이 아니다. 루트 `package.json` 이 `backend` 를
> workspace 로 물고 있고, 배포도 루트에서 설치한다.

## 2. MySQL 띄우기 (각자 자기 PC 에)

**팀원끼리 DB 를 공유하지 않는다.** 각자 로컬에 하나씩 띄운다 — 스키마를 바꾸는
작업이 서로를 깨뜨리지 않게 하기 위해서다.

```bash
docker run -d --name careerly-mysql \
  -e MYSQL_ROOT_PASSWORD=careerly_dev \
  -e MYSQL_DATABASE=careerly \
  -p 3306:3306 mysql:8.0 \
  --character-set-server=utf8mb4 --collation-server=utf8mb4_unicode_ci
```

두 번째부터는 `docker start careerly-mysql` 만 하면 된다.
**DB 가 떠 있지 않으면 서버는 일부러 죽는다** (살아있는 척하면 원인을 못 찾는다).

## 3. `.env` 만들기

```bash
cp backend/.env.example backend/.env
```

`DB_PASSWORD=careerly_dev` 를 채운다(2번에서 정한 값). 나머지 API 키는
**팀에서 1:1 로 전달받는다** — 저장소·단톡방·문서에 붙여넣지 않는다.

키를 하나도 안 넣어도 서버는 뜨고 대부분의 화면이 동작한다. 빠지는 것은
AI 분석·뉴스·소셜로그인·결제뿐이다.

> ⚠️ **값 칸에 `KEY=값` 을 통째로 붙여넣지 않는다.** `GROQ_API_KEY=GROQ_API_KEY=gsk_...`
> 같은 형태가 되면 **비어 있지 않으니 '켜짐' 으로 보이는데 호출만 실패한다.**
> 배포에서 실제로 밟은 함정이라(작업정리 13-3) 지금은 부팅 때 경고를 찍는다 —
> 로그를 확인할 것.

### 공유 키를 쓸 때 알아둘 것

| | |
|---|---|
| Groq | **무료 티어 rate limit 을 팀이 공유**한다. 여럿이 동시에 AI 분석을 돌리면 429 가 난다. 급하면 `console.groq.com` 에서 각자 키를 발급받아 자기 `.env` 에만 넣는다(무료·카드 불필요) |
| 네이버·카카오 로그인 | 콘솔에 `http://localhost:3000` 콜백이 등록돼 있어야 팀원 PC 에서도 로그인이 된다. 이미 등록돼 있으니 그대로 쓴다 |
| 네이버 **'개발 중' 상태** | 키·콜백이 다 맞아도 **등록된 아이디만** 로그인된다. `현재 careerly는 개발 중 상태입니다...` 가 뜨면 이것이다 — 코드를 뒤지지 말 것. 개발자센터 → 애플리케이션 → **API 설정 → 멤버관리**에 네이버 아이디를 추가하면 즉시 풀린다(최대 10명). 일반 공개는 **검수 요청** 필요 |
| 토스 | `test_ck_` / `test_sk_` 테스트 키다. 실제 카드번호를 넣어도 가상 승인이라 돈이 나가지 않는다 |
| 운영 DB | **공유 대상이 아니다.** 운영 접속 정보는 배포를 하는 사람만 쓴다 |

## 4. 스키마와 카탈로그 넣기

```bash
cd backend
node scripts/load-schema.js                  # 테이블 13개
node scripts/migrate-to-mysql.js --catalog   # 자격증643·학과193·기업6,634·직업461
```

두 스크립트 모두 **어느 DB 에 넣는지 먼저 찍고 시작한다.** 주소가 로컬
(`root@127.0.0.1:3306/careerly`)이 맞는지 보고 진행한다.

### 기업분석을 쓰려면 한 번 더 (선택)

```bash
npm run build      # 루트에서. DART 기업 색인 11만여 건(6MB)을 받는다
```

`backend/data/dart-corps.json` 은 **깃에 없다** — 6MB 짜리가 받을 때마다 히스토리에
쌓여서 뺐다(`.gitignore`). 회사 이름을 DART 고유번호로 바꾸는 색인이라 이게 없으면
기업분석의 개요·재무·경쟁사 칸이 빈다(다른 기능은 멀쩡하다).

`.env` 의 `DART_API_KEY` 가 있어야 하고, 없으면 **건너뛴다**(에러가 아니다).
지금 어느 쪽인지는 서버 부팅 로그의 `[기능] … 기업분석` 에 찍힌다.

## 5. 서버 띄우기

```bash
npm run dev        # 루트에서. nodemon → http://localhost:3000
```

부팅에 성공하면 두 줄이 뜬다:

```
[mysql] 연결됨 ...
[기능] 결제 켜짐 · 네이버로그인 켜짐 · 카카오로그인 켜짐 · AI 켜짐 · 뉴스 ncp
```

**두 번째 줄로 어떤 키가 읽혔는지 바로 알 수 있다.** `뉴스 web` 이면 검색 키가
안 읽힌 것이고(웹 폴백), 이 상태는 기사가 나오긴 해서 **'되는데 이상한' 모습**이다.

`frontend/careerly.html` 을 파일로 직접 열면 **동작하지 않는다** — 데이터가
전부 서버 API 에 있다. 반드시 `http://localhost:3000` 으로 들어간다.

## 7. 브랜치 규칙

```
main       운영. 직접 푸시하지 않는다. Railway production 이 자동 배포
dev        통합 브랜치(기본 브랜치). Railway staging 이 자동 배포
feature/*  각자 작업
```

```bash
git switch dev && git pull
git switch -c feature/짧은-설명
# ...작업...
for f in test/*.test.js; do node "$f" | tail -1; done   # 전부 통과해야 한다
git push -u origin feature/짧은-설명
# GitHub 에서 dev 로 PR → 다른 사람 1명 승인 → Squash merge
```

배포는 `dev` → `main` PR 로만 한다. 절차는 `docs/배포.md` 8장.

## 8. 하지 말 것

| | 왜 |
|---|---|
| `.env` 커밋 | `.gitignore` 에 있지만 `-f` 로 넣으면 들어간다. 키가 깃 히스토리에 남으면 전부 재발급해야 한다 |
| 셸에 `MYSQL_URL` 을 켜둔 채 로컬 작업 | **로컬 작업이 운영/스테이징 DB 를 건드린다.** 원격 DB 에 스크립트를 돌렸으면 곧바로 `Remove-Item Env:MYSQL_URL`(PowerShell) / `unset MYSQL_URL` |
| `main` 에 직접 푸시 | 검증 안 된 코드가 곧바로 운영에 나간다 |
| 새 라우트·새 파일 추가 후 서버 그대로 두기 | `npm run dev`(nodemon)로 띄웠으면 자동 재시작된다. `npm start` 로 띄웠으면 직접 재시작 |
| 배점 상수를 backend 에 새로 적기 | 배점의 단일 출처는 `frontend/js/cas.js` 하나다. 백엔드도 여기서 읽는다 |
