지금 화면이 불편한 이유 4가지

① 회사 검색은 짙은 보라 사이드바가 화면을 다 먹는데 본문에는 볼 게 없다 · ② 입력칸 4개가 작아서 붙여넣고 나면 내가 뭘 썼는지 다시 못 본다 · ③ 분석 결과가 세로로만 길어 역량 하나를 확인하려면 계속 스크롤해야 하고, 요구역량과 직무역량이 따로 나온다 · ④ 초안을 쓸 때 역량 가이드가 화면 밖으로 밀려난다. 아래 9안은 각각 이 넷 중 무엇을 어떻게 없앴는지로 갈린다.

A-1PART A · 회사 찾기

기업 리포트형

사이드바를 흰색 목록으로 낮추고, 본문을 “이 회사에 대해 자소서에 쓸 수 있는 사실”로 가득 채웁니다. 지금 화면의 안내문 4칸이 실제 데이터(재무·기사·공고·경쟁사)로 바뀝니다.

REF사람인 기업정보잡플래닛Glassdoor CompanyLevels.fyi

지금

  • #181818 + 보라 그라데이션 사이드바가 286px을 차지하는데, 담긴 건 검색창과 회사 7개뿐
  • 본문은 “1 회사 움직임 → 2 직무 연결 → 3 내 경험 → 4 기여” 안내문 4칸. 회사를 바꿔도 내용이 안 바뀐다
  • 재무·기사는 자소서 코치 쪽 ‘이 회사 분석하기’를 눌러야 나온다 — 회사 페이지에 없다

이 안

  • 사이드바는 흰 배경 + 헤어라인. 검색·최근 본 회사·관심 회사만 남기고 폭 248px로 축소
  • 본문 = 기업 리포트. 규모/설립/사원수 → 실적 4칸(스파크라인) → 최근 기사 → 반복 키워드 순
  • 우상단 지원동기 근거 3/5 게이지. 이 페이지에 온 이유가 숫자로 보인다
  • 기사 제목 옆 [근거로 담기] — 담은 사실이 자소서 코치 지원동기 문항에 그대로 붙는다
A-2PART A · 회사 찾기

검색 우선형 — 사이드바를 없앤다

고정 사이드바를 통째로 제거하고 검색을 화면 한가운데로 올립니다. 검색 전에는 “지금 마감 임박”, “내 전공과 맞는 회사”가 카드로 깔려서 빈 화면이 없습니다.

REFIndeed Company Search원티드사람인 기업 검색Otta

지금

  • 검색창이 어두운 사이드바 안에 갇혀 있어 “이 페이지의 주된 행동”으로 안 읽힌다
  • 추천 7곳이 하드코딩 — 나와 무관한 회사가 항상 같은 순서로 뜬다
  • 회사를 고르기 전에는 본문이 텅 빈 안내문

이 안

  • 사이드바 삭제 → 화면 전체가 본문. 검색창 하나가 화면 최상단 중앙
  • 입력 즉시 드롭다운에 회사명 + 업종 + 규모 + 채용중 공고 수까지 한 줄에
  • 검색 전 화면: 마감 임박 / 내 전공 맞춤 / 최근 분석 3레인 — 누를 것이 항상 있다
  • 결과는 카드 그리드 + 체크박스 비교하기 (2~3곳 나란히 두고 지원처 결정)
A-3PART A · 회사 찾기

지원 관리 보드형 — 페이지에 일을 준다

“왜 있는지 궁금한 페이지”를 내 지원 현황판으로 바꿉니다. 회사 검색은 이 보드에 회사를 추가하는 수단이 되고, 페이지의 존재 이유가 “지금 어디까지 썼는지”가 됩니다.

REFTeal Job TrackerHuntr사람인 입사지원 현황LinkedIn My Items

지금

  • 회사를 골라도 남는 게 없다 — 회사명 한 개만 자소서 코치로 넘어가고 끝
  • 어제 어디까지 썼는지 알 방법이 없다. 초안은 localStorage 안에만 있고 목록이 없다
  • 마감일 개념이 화면 어디에도 없다

이 안

  • 상단 스트립: 이번 주 마감 2건 — 페이지를 연 순간 할 일이 보인다
  • 단계 필터(관심 / 준비중 / 작성중 / 제출완료)로 왼쪽 사이드바를 대체 — 어두운 패널이 사라진다
  • 행마다 자소서 진행률 bar + 근거 확보 뱃지 + 남은 문항 수 → [이어쓰기] 한 번에 그 문항으로
  • 회사 검색은 우상단 + 지원할 회사 추가 안의 모달로 내려간다
B-1PART B · 입력 4칸

문서형 에디터 — 칸을 없애고 문서 하나로

rows 고정 textarea를 내용만큼 자라는 블록으로 바꿉니다. 다 쓴 항목은 접히고, 접힌 상태에서도 첫 두 줄과 글자수가 보여서 “내가 뭘 넣었는지”가 항상 확인됩니다.

REFNotionGoogle Docs 개요LinearCraft

지금

  • rows="8" 고정 — 2,000자를 붙여넣어도 보이는 건 8줄, 나머지는 내부 스크롤
  • 4칸이 세로로 붙어 있어서 3번을 고치는 동안 2번에 뭘 넣었는지 안 보인다
  • 어느 칸이 채워졌는지 한눈에 안 보임 — 다 똑같이 생긴 회색 박스

이 안

  • 입력칸이 내용만큼 자란다(auto-grow). 스크롤 안에 스크롤이 생기지 않는다
  • 블록마다 접기 / 전체화면. 접으면 미리보기 2줄 + 글자수만 남아 4칸이 한 화면에
  • 왼쪽 개요에 채움 상태(● 채움 / ○ 빈칸)와 글자수 — 클릭하면 그 블록으로
  • 상단 고정바에 저장 상태와 분석하기. 어디까지 스크롤해도 버튼이 따라온다
B-2PART B · 입력 4칸

단계형 위저드 — 한 번에 하나, 마지막에 전체 검토

한 화면에 입력칸 하나만 두고 화면 높이만큼 크게 씁니다. 대신 마지막에 4개를 카드로 모아 보여주는 검토 단계를 넣어, 제출 전에 뭘 넣었는지 반드시 한 번 훑게 만듭니다.

REF원티드 지원서Typeform토스 온보딩잡코리아 이력서 작성

지금

  • 네 칸이 동시에 보이지만 각각 작아서, 결국 어느 것도 편하게 못 쓴다
  • 어디까지 했는지 알려주는 장치가 없다 — 오른쪽 보라 바로가기는 이동만 시켜준다
  • 다 입력하고 나서 전체를 되짚어 보는 지점이 없다

이 안

  • 입력창 하나가 화면 높이의 절반 이상. 긴 공고도 스크롤 없이 한눈에
  • 상단 진행바 4칸 — 완료된 단계는 눌러서 바로 되돌아갈 수 있다
  • 오른쪽에 붙여넣는 법 예시와 앞 단계 요약. 지금 뭘 넣는지 헷갈릴 일이 없다
  • 마지막 검토 단계에서 4개를 카드로 모아 보고, 카드 안에서 바로 수정
B-3PART B · 입력 4칸

좌우 분할 — 붙여넣는 즉시 오른쪽에서 구조가 보인다

왼쪽은 탭으로 바뀌는 큰 입력창 하나, 오른쪽은 지금 입력한 게 어떻게 인식됐는지를 실시간으로 보여주는 패널. “내가 적은 내용 확인하기 어렵다”를 가장 직접적으로 푸는 안입니다.

REFGrammarly 에디터원티드 JD 파서Notion AI 사이드패널Linear 이슈 분할뷰

지금

  • 붙여넣은 텍스트가 제대로 들어갔는지, 문항이 3개로 잘 쪼개졌는지 분석을 돌려야만 안다
  • 문항을 “한 줄에 하나씩” 넣어야 하는데 그 규칙이 지켜졌는지 화면이 말해주지 않는다
  • 공고에서 어느 문장이 역량 근거로 쓰이는지 나중에야 알게 된다

이 안

  • 왼쪽 탭에 글자수 배지 — 어느 칸이 비었는지 탭 줄만 봐도 안다
  • 오른쪽에 [주요업무] [자격요건] [우대사항] 자동 분해 카드. 인식 안 된 문단은 회색으로 남는다
  • 역량 후보 키워드를 원문에 노란 하이라이트로 표시 — 분석 전에 오탐을 먼저 걸러낼 수 있다
  • 문항 탭에서는 오른쪽이 문항 1·2·3 카드로 바뀌어, 줄바꿈이 잘못됐으면 바로 보인다
C-1PART C · AI 답변

역량 ↔ 초안 2단 분할

왼쪽에 역량 목록(요구역량 = 직무역량 하나로 통합), 오른쪽에 초안 에디터를 고정합니다. 역량을 보면서 그 자리에서 쓰기 — 3번과 4번 요청을 한 화면으로 동시에 푸는 안입니다.

REFGrammarly 에디터Notion AI 사이드패널JasperTeal Resume Builder

지금

  • 역량 카드 7개가 세로로 쌓여 카드 하나가 화면보다 길다. 3번 역량을 보려면 계속 내려야 한다
  • 요구역량 카드(#jd-result)와 문항별 직무역량 카드(#jd-questions-result)가 따로 나와 같은 말을 두 번 읽는다
  • 초안 작성칸이 카드 맨 아래라, 쓰기 시작하면 가이드가 화면 위로 사라진다

이 안

  • 왼쪽 목록은 한 줄 요약(역량명 · 시장빈도 · 내 근거 유무)으로 압축 — 7개가 한 화면에
  • 고른 역량만 그 자리에서 펼쳐진다. 근거 문장 → 쓰는 순서 → 숫자 → 감점이 접힌 채로
  • 문항별 배분은 역량 줄에 문항 뱃지(①②③)로 흡수 — 카드가 두 벌 나오지 않는다
  • 오른쪽 에디터는 스크롤해도 고정. [이 순서 삽입]이 뼈대를 초안에 바로 넣는다
  • 에디터 하단에 글자수·빈칸·상투표현 검사가 항상 붙어 있다
C-2PART C · AI 답변

커버리지 대시보드 — 먼저 전체, 그 다음 하나

스크롤을 없애는 다른 방법: 역량 7개를 카드 그리드로 한 화면에 깔고, 누른 하나만 오른쪽 드로어로 펼칩니다. 맨 위 커버리지 요약이 “뭐부터 손대야 하는지”를 먼저 알려줍니다.

REFGlassdoor 대시보드Levels.fyiLinear사람인 역량진단

지금

  • 7개 카드를 다 읽어야 “내가 뭘 못 채웠는지” 알 수 있다 — 요약이 없다
  • 칩을 눌러 하나만 보는 필터는 있지만, 다시 전체를 볼 때 맥락이 끊긴다
  • 시장 빈도·내 근거·문항 배분이 카드마다 흩어져 서로 비교가 안 된다

이 안

  • 상단 요약: 7개 중 4개 커버 / 3개 부족 + 부족한 역량 이름을 바로 지목
  • 카드는 4줄로 압축(역량명 · 빈도 · 커버 상태 색띠 · 내 소재 1줄) — 7개가 두 줄 안에
  • 카드를 누르면 오른쪽 드로어. 페이지 위치가 안 바뀌니 다음 카드로 옮겨 다니기가 쉽다
  • 드로어 하단이 곧 초안 작성칸 — 가이드와 작성이 같은 패널 안에
  • 왼쪽 색띠: 초록=근거 충분 / 노랑=약함 / 빨강=근거 없음
C-3PART C · AI 답변

문항 중심 워크스페이스 — 결국 제출하는 건 문항이니까

화면의 최상위 단위를 자소서 문항으로 바꿉니다. 탭 하나 = 문항 하나이고, 그 안에서 에디터가 주인공, 역량은 오른쪽 팔레트가 되어 클릭하면 초안에 뼈대가 들어갑니다.

REF자소설닷컴Teal AI ResumeNotion 데이터베이스 탭Grammarly Goals

지금

  • 문항 카드와 역량 카드가 서로 다른 블록에 있어서, 2번 문항을 쓰는 동안 필요한 역량 가이드가 다른 곳에 있다
  • 같은 역량을 여러 문항에 중복해서 쓰고 있는지 확인할 방법이 없다
  • 글자수 제한(회사가 지정하는 700자/1,000자)을 다루는 UI가 없다

이 안

  • 탭 = 문항. 탭에 글자수 / 제한 / 완료 여부가 붙어 제출 상태가 항상 보인다
  • 문항 전문이 에디터 위에 고정 — 쓰다가 질문을 잊지 않는다
  • 오른쪽 역량 팔레트: 이 문항에 배정된 역량 + 내 경험 카드. 누르면 뼈대가 커서 위치에 삽입
  • 이미 다른 문항에 쓴 소재는 회색으로 잠긴다 — 중복 소재를 구조적으로 막는다
  • 하단 고정바에 글자수·검사·저장. 아래로 스크롤해도 제출 상태가 사라지지 않는다
