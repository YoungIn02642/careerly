# 외부 API 연동 구조

커리얼리가 외부 서비스(정부 공공데이터, AI 등)의 정보를 가져다 쓰는 방식과,
새로운 외부 서비스를 붙일 때의 절차를 정리한다.

---

## 5분 요약

한 줄로 말하면:

> **필요한 정보를 남의 창고에서 가져다 쓰는데, 그 창고 열쇠는 우리 서버 금고에만 두고
> 손님(브라우저)한테는 절대 주지 않는다.**

### 왜 열쇠를 손님한테 안 주나

브라우저에서 보이는 건 누구나 열어볼 수 있다. F12 만 누르면 화면 쪽 코드가 다 보인다.
그래서 열쇠(API 키)를 화면 코드에 넣으면 그냥 공개하는 것과 같다.

그래서 **항상 서버가 대신 다녀온다.**

```
사용자 화면  →  우리 서버  →  외부 서비스
            ←            ←
         (열쇠는 이 안에서만)
```

### 다녀오는 방식이 두 가지다

**방식 A — 미리 장 봐두기 🥫**

"공공기관 명단", "대기업 명단" 같은 건 1년에 한두 번 바뀐다. 사용자가 회사명 칠 때마다
정부 사이트에 물어보는 건 낭비다. 느리고, 하루 호출 횟수 제한도 있다.

그래서 **개발자가 미리 한 번 받아와 파일로 저장해둔다.** 냉장고에 장을 봐두는 것과 같다.
사용자가 "삼성전자" 를 입력하면 서버는 냉장고만 열어보고 즉시 "대기업입니다" 라고 답한다.
정부 사이트에는 연락하지 않는다 — 빠르고, 정부 사이트가 멈춰도 우리는 멀쩡하다.

명단이 갱신되면 개발자가 스크립트를 다시 돌려 장을 다시 본다.

**방식 B — 그때그때 주문하기 🛵**

AI 스펙 분석은 미리 저장이 불가능하다. 사람마다 쓰는 내용이 다르기 때문이다.
사용자가 활동 내역을 글로 쓰면 → 서버가 그 글을 AI 에게 보내고 → AI 가 "대외활동,
6개월, 팀장, 수상, 몇 점" 식으로 정리해 돌려주면 → 서버가 형식을 다듬어 화면에 표시한다.

매번 배달을 시키는 셈이라 느리다(최대 4분). 그래서 무한정 기다리지 않게 시간 제한을 뒀다.

**판단 기준은 간단하다: 자주 안 바뀌는 정보면 A, 요청마다 달라지면 B.**

### 화면 쪽은 창구가 하나다

화면 코드가 서버에 말을 거는 창구는 `frontend/js/db.js` 파일 하나뿐이다.
로그인이든 스펙 저장이든 AI 분석이든 전부 이 창구를 거친다. 화면 파일이 10개쯤 되지만
그 어느 것도 서버에 직접 말을 걸지 않는다.

이렇게 해둔 이유는 **나중에 규칙이 바뀔 때 한 군데만 고치면 되기 때문**이다.
예를 들어 "모든 요청에 로그인 정보를 같이 보내라"는 규칙을 한 줄로 처리하고 있다.
창구가 10개였다면 10군데를 고쳐야 한다.

### 열쇠는 어디 있나

`backend/.env` 파일에 있다. 이 파일은 **깃허브에 올라가지 않는다**(일부러 제외해뒀다).
대신 `.env.example` 이라는 **빈 양식**만 올라간다 — 어떤 열쇠가 필요한지와 발급 주소만
적혀 있고 실제 값은 비어 있다. 새로 참여하는 사람은 이 양식을 복사해 자기 열쇠를 채우면 된다.

## 두 방식 비교

| | 방식 A — 미리 장 봐두기 | 방식 B — 그때그때 주문 |
|---|---|---|
| 언제 외부에 연락하나 | 개발자가 스크립트를 **수동 실행할 때만** | 사용자 요청이 올 때마다 |
| 쓰는 곳 | 공공데이터포털, 고용24 | CAS AI 분석 |
| 중간 저장 파일 | `backend/data/*.json` (깃에 커밋됨) | 없음 |
| 응답 속도 | 즉시 (파일만 읽음) | 느림 (AI 대기, 최대 4분) |
| 외부가 멈추면 | 아무 영향 없음 | 그대로 실패 |

## 방식 A — 미리 장 봐두기

### 흐름

```
backend/.env  (열쇠 보관)
   │
   ▼  개발자가 손으로 실행:  node scripts/fetch-ftc-groups.js
backend/scripts/fetch-*.js  ──인터넷──▶  정부 API
   │
   ▼  받아온 걸 파일로 저장
backend/data/ftc-large-groups.json  등
   │
   ▼  서버가 켜질 때 파일을 한 번 읽어둠
backend/src/company-classify.js
   │
   ▼  이제 사용자 요청에 즉시 응답
GET /api/company/classify?name=삼성전자
```

### 장 보는 스크립트들 (`backend/scripts/`)

| 스크립트 | 어디서 받아오나 | 저장 파일 | 무엇에 쓰나 |
|---|---|---|---|
| `fetch-ftc-groups.js` | 공정위 대규모기업집단 | `ftc-large-groups.json` | 대기업 판별 |
| `fetch-public-orgs.js` | 공공기관 지정현황 | `public-orgs.json` | 공공기관 판별 |
| `fetch-local-public-orgs.js` | 지방공기업 CSV | `local-public-orgs.json` | 지방공기업 판별 |
| `fetch-ncs-taxonomy.js` | NCS 직무분류 | `ncs-taxonomy.json` | 직무 분류 |
| `check-api-access.js` | — | — | 내 열쇠가 승인됐는지 점검 |

열쇠를 읽는 부분은 스크립트 맨 위에 모여 있다 (`fetch-ftc-groups.js:26`):

```js
const KEY = (process.env.DATA_GO_KR_SERVICE_KEY || '').trim();
const API = 'https://apis.data.go.kr/1130000/appnGroupAffiList/appnGroupAffiListApi';
...
if (!KEY) throw new Error('DATA_GO_KR_SERVICE_KEY 가 .env 에 없습니다.');
```

### 기억할 것

- **서버가 돌아가는 중에는 외부에 연락하지 않는다.** `company-classify.js` 는
  저장된 파일만 본다. 그래서 회사명을 한 글자씩 칠 때마다 자동판정이 돌아도
  즉시 답하고, 정부 API 호출 횟수도 쓰지 않는다.
- **자동판정은 어디까지나 추천이다.** 최종 기업유형은 회원이 화면에서 고른 값을
  그대로 저장한다. 명단에 없는 회사가 훨씬 많기 때문에 자동판정으로 덮어쓰지 않는다.
- 장을 제대로 봤는지 확인: `GET /api/company/stats`

## 방식 B — 그때그때 주문 (CAS AI 분석)

### 흐름

```
화면    DB.analyzeSpec(글)                 frontend/js/db.js:96
   │
   ▼  POST /api/cas/analyze  { text }
서버    src/routes/casAnalyze.js
   │      .env 의 CAS_AI_PROVIDER 설정을 보고 어디로 보낼지 정함
   │        ├─ ollama (기본) → 내 컴퓨터에 깔린 AI
   │        └─ groq          → 인터넷 AI
   │
   ▼  AI 가 답을 반드시 JSON 형식으로 주도록 강제
   ▼  답에 이상한 값이 섞이면 정해진 항목으로 교정
   ▼  우리가 직접 계산한 점수도 같이 넣어 서로 대조
   │
   ◀── 정리된 결과를 화면으로
```

### 알아둘 점

- **점수 기준표는 한 군데에만 있다.** `frontend/js/cas.js` 의 배점표를 그대로 읽어
  AI 프롬프트에 넣는다. 화면과 서버가 같은 표를 보므로 점수가 어긋나지 않는다.
- **모델이 안 깔려 있으면 알아서 대체한다.** 지정한 AI 모델이 없으면 설치된 것 중
  이 작업에 잘 맞는 순서로 골라 쓴다. 사용자에게 설치를 강요하지 않는다.
- **일부 AI 는 혼잣말을 한다.** qwen3 같은 모델은 생각 과정을 같이 뱉어서 JSON 형식을
  깨뜨린다. 그걸 끄는 옵션을 붙였다.
- **시간 제한.** 내 컴퓨터에서 도는 AI 는 느리다. 화면이 무한정 기다리지 않도록
  기본 4분 상한을 뒀다 (`CAS_AI_TIMEOUT_MS`).

### 왜 내 컴퓨터 AI 가 기본인가

**열쇠도, 사용량 제한도, 인터넷도 필요 없기 때문이다.** 처음엔 Gemini 로 붙였는데
구글 계정이 무료 사용을 지원하지 않았고(프로젝트를 새로 만들어도 마찬가지), Groq 으로
옮겼다가, 최종적으로 로컬 Ollama 를 기본으로 했다.

단, **실제로 배포할 때는 Groq 으로 바꿔야 한다** — 서버 컴퓨터에는 AI 를 설치할 수 없다.

## 화면에서 서버를 부르는 방법

모든 호출은 `frontend/js/db.js` 의 `api()` 함수 하나를 통한다 (`db.js:25`).

```js
async function api(method, path, body) {
  const res = await fetch(path, {
    method,
    credentials: 'include',                 // 로그인 정보(쿠키)를 같이 보냄
    headers: body ? { 'Content-Type': 'application/json' } : undefined,
    body: body ? JSON.stringify(body) : undefined,
  });
  let data = null;
  try { data = await res.json(); } catch { /* 본문 없음 */ }
  if (!res.ok) throw new Error(data?.error || `요청에 실패했습니다. (${res.status})`);
  return data;
}
```

### 규칙

- **주소를 짧게 쓴다.** 화면과 서버를 같은 서버가 함께 내보내기 때문에
  `https://...` 같은 전체 주소가 필요 없다. `/api/specs` 처럼만 쓴다.
- **화면 코드는 서버를 직접 부르지 않는다.** `career.js`, `home.js`, `spec-form.js` 등은
  `DB.xxx()` 만 부른다. 실제로 `fetch(` 가 등장하는 화면 파일은 `db.js` 하나뿐이다.
- **읽기는 빠르게, 쓰기는 기다린다.** 앱이 켜질 때 서버 데이터를 한 번 받아 메모리에
  저장해두고, 화면을 그리는 도중의 읽기는 그 메모리에서 즉시 준다. 데이터를 바꾸는
  동작만 서버 응답을 기다린다.
- **로그인 안 한 상태의 401 은 오류가 아니다.** 정상 상태이므로 조용히 넘긴다.

### 외부 서비스와 닿는 두 함수

```js
// db.js:87 — 방식 A. 저장된 파일만 보므로 사실상 즉답
return await api('GET', `/api/company/classify?name=${encodeURIComponent(name.trim())}`);

// db.js:96 — 방식 B. AI 왕복이라 느림
return api('POST', '/api/cas/analyze', { text });
```

## 열쇠 보관과 불러오기

- 진짜 열쇠는 `backend/.env` — **깃허브에 올라가지 않는다.**
- 빈 양식은 `backend/.env.example` — 올라간다. **여기에 실제 열쇠를 넣으면 안 된다.**
  각 항목마다 어디서 발급받는지, 어느 스크립트가 쓰는지 주석으로 적혀 있다.
- 서버가 켜질 때 맨 첫 줄에서 읽는다 (`src/server.js:1`):

```js
require('dotenv').config({ path: require('path').join(__dirname, '..', '.env') });
```

### 현재 항목

| 항목 | 꼭 필요한가 | 설명 |
|---|---|---|
| `DATA_GO_KR_SERVICE_KEY` | 방식 A 에 필요 | 공공데이터포털. 계정당 하나로 승인된 API 전부 사용 |
| `WORK24_API_KEY` | 선택 | 고용24. 비워두면 중견기업 자동판정만 빠지고 나머지는 정상 |
| `CAS_AI_PROVIDER` | 선택 | `ollama`(기본) 또는 `groq` |
| `OLLAMA_HOST` / `OLLAMA_MODEL` | 선택 | 기본값 `http://127.0.0.1:11434` / `qwen3:8b` |
| `CAS_AI_TIMEOUT_MS` | 선택 | AI 대기 상한. 기본 4분 |
| `NODE_ENV` / `ALLOWED_ORIGINS` | 배포할 때 | 아래 "배포 시 주의" 참고 |

**열쇠는 서버에서만 읽는다. 화면으로는 절대 내려가지 않는다.** 새 외부 서비스를 붙일
때도 반드시 서버에 `/api/...` 통로를 만들어 중계해야 한다. 화면에서 외부를 직접 부르면
열쇠가 브라우저에 노출된다.

## 새 외부 서비스를 붙이는 순서

**먼저 공통** — `.env.example` 에 항목과 발급처 주석을 추가하고, `.env` 에 실제 열쇠를 넣는다.

### 자주 안 바뀌는 정보라면 → 방식 A

1. `backend/scripts/fetch-XXX.js` 를 만든다. 맨 위에서 열쇠를 읽고, 없으면 무슨 열쇠가
   없는지 분명히 알려주며 멈춘다.
2. 실행해서 `backend/data/XXX.json` 을 만든다. 이 파일은 **깃에 커밋한다** —
   다른 사람이 열쇠 없이도 앱을 돌릴 수 있어야 한다.
3. `src/` 의 조회 코드에서 서버 시작 시 한 번 읽어둔다.
4. 필요하면 조회용 `/api/...` 통로를 추가한다.

### 요청마다 달라지는 정보라면 → 방식 B

1. `backend/src/routes/XXX.js` 를 만든다. 설정값은 파일 맨 위에서 상수로 뽑아둔다.
2. **시간 제한과 설정 누락 처리를 반드시 넣는다.** 외부가 멈췄을 때 화면이 영영
   기다리면 안 되고, 열쇠가 없으면 "설정이 안 됐다" 고 분명히 알려야 한다.
3. `src/server.js` 에 등록한다:
   ```js
   const xxxRouter = require("./routes/XXX");
   app.use("/api/xxx", xxxRouter);
   ```
4. `frontend/js/db.js` 에 `api()` 를 쓰는 함수 하나를 추가한다. 화면 코드는 그것만 부른다.

## 배포 시 주의

`NODE_ENV=production` 을 켜면 세 가지가 달라진다.

1. **외부 접속 차단이 켜진다.** 개발 중에는 어디서 접속하든 허용하는데, 그대로 두면
   다른 사이트가 우리 사용자의 로그인 정보를 몰래 쓰는 공격에 노출된다.
   `ALLOWED_ORIGINS` 에 배포 도메인을 반드시 적어야 한다(안 적으면 전부 차단).
2. **로그인 쿠키가 HTTPS 에서만 오간다.** Render 같은 호스팅 뒤에서도 이게 동작하도록
   설정은 이미 넣어뒀다.
3. **백오피스가 전부 막힌다.** 회원 목록·삭제·초기화 기능은 아직 관리자 권한 체계가
   없어서 운영 환경에서는 404 로 숨긴다.

그 밖에:

- `CAS_AI_PROVIDER=groq` 로 바꾸고 Groq 열쇠를 넣는다. 서버에는 AI 를 설치할 수 없다.
- `backend/data/*.json` 이 깃에 들어가 있어야 배포 환경에서 기업분류가 동작한다.
