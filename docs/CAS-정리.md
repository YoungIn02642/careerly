# careerly CAS 정리

작성일: 2026-07-21

CAS(Career Asset Score) 점수 체계와 AI의 역할, 그리고 화면에 넣을 설명 문구를 한곳에 모았습니다.
사용자에게 보여줄 문구는 인용문(>)으로 표시했습니다.

---

## 1. CAS는 어떻게 계산되나

### 두 종류의 스펙

| 구분 | 코드상 이름 | 만점 | 내용 |
|---|---|---|---|
| 숫자 스펙 | 정량(quant) | 400점 | 학점 · 어학 · 자격증 |
| 경험 스펙 | 정성(qual) | 600점 | 인턴 · 공모전 · 대외활동 · 프로젝트 등 |
| **합계** | | **1,000점** | |

> **내 역량 자산 점수 (CAS)**
> 학점·어학·자격증 같은 **숫자로 남는 스펙**과, 인턴·공모전·동아리 같은 **경험으로 쌓이는 스펙**을 합쳐 1,000점으로 나타낸 점수예요. 취업에 성공한 선배들의 실제 데이터와 비교해 계산하기 때문에, 내가 지금 어디쯤 와 있는지 가늠할 수 있어요.

### 채점의 기본 원칙 — 절대평가가 아니라 상대평가

모든 항목은 **합격한 선배 평균과 비교**해서 점수가 정해집니다.

- 선배 평균과 같음 → 만점의 **80%**
- 선배 평균의 **1.25배 이상** → **만점**
- 0 → 0점 (평균 미만 구간은 선형으로 이어짐)

이 규칙(`CAS.relativeScore`)은 학점·어학·자격증·경험 점수·비교 막대까지 **전부 같은 자**를 씁니다.
그래서 "막대는 긴데 점수는 낮다" 같은 어긋남이 생기지 않습니다.

### 경험 스펙 점수 매기는 법

```
활동 1건 점수 = 기본배점 × 기간배수 × 역할배수 × 성과배수
```

기본배점(활동 유형별):

| 활동 | 배점 | 활동 | 배점 |
|---|---|---|---|
| 인턴십 | 100 | 학부연구생·석사·박사 | 58 |
| 공모전·대회 | 78 | 동아리·학회 | 46 |
| 대외활동(서포터즈·기자단) | 74 | 교환학생·어학연수 | 40 |
| 프로젝트 | 62 | 봉사활동 | 30 |
| | | 기타 | 24 |

상위 최대 6개 활동의 합을 선배 평균과 비교해 600점 만점으로 환산합니다.

> **경험 스펙 — 인턴·공모전·대외활동**
> 숫자로 표현하기 어려운 경험들이에요. careerly는 **활동 종류 × 얼마나 오래 했는지 × 어떤 역할이었는지 × 어떤 결과를 냈는지**로 점수를 매깁니다. 예를 들어 6개월 인턴을 팀장으로 하며 성과를 낸 경험이, 한 달짜리 참여형 활동보다 높게 계산돼요.

## 2. 정량:정성 비중은 왜, 어떻게 바뀌나

### 원칙

기본은 **숫자 4 : 경험 6**입니다. 하지만 고정이 아니라 **내가 더 잘한 쪽에 비중을 더 실어줍니다.**
학점은 평범해도 경험이 압도적이라면 그 강점이 점수에 반영돼야 하기 때문입니다.

- 범위: **최소 3:7 ~ 최대 5:5** (한쪽이 아무리 뛰어나도 다른 쪽이 무의미해지지 않음)
- 판단 기준: 두 축의 **달성도**(획득점수 ÷ 만점)를 비교
- 달성도 차이가 **20%p** 벌어지면 끝(3:7 또는 5:5)에 도달, 그 사이는 비례해서 매끄럽게 이동

> 잘한 쪽에 비중을 더 실어줍니다. 기본 4:6에서 시작해 경험이 강하면 3:7까지, 숫자 스펙이 강하면 5:5까지 움직여요.

### 예시 3가지 (실제 코드로 계산한 값)

**예시 1 — 두 쪽이 비슷한 경우 → 4:6 (기본)**

> 학점·어학도 평균 이상, 인턴·대외활동도 꾸준히 해온 학생.
> 숫자 스펙 70% 달성 · 경험 스펙 70% 달성
> → **숫자 280점 + 경험 420점 = 700점**

**예시 2 — 경험이 강한 경우 → 3:7**

> 학점은 딱 중간인데, 인턴 2회에 공모전 수상까지 있는 학생.
> 숫자 스펙 50% 달성 · 경험 스펙 80% 달성
> → **숫자 150점 + 경험 560점 = 710점**
>
> 숫자 스펙이 예시 1보다 한참 낮은데도 **총점은 더 높습니다.** 경험으로 뒤집은 경우예요.

**예시 3 — 숫자 스펙이 강한 경우 → 5:5**

> 학점 4.2에 토익 950, 자격증도 여러 개인데 대외 경험은 아직 적은 학생.
> 숫자 스펙 85% 달성 · 경험 스펙 50% 달성
> → **숫자 425점 + 경험 250점 = 675점**
>
> 경험 비중이 5 아래로 내려가지 않기 때문에 **학점만으로 만점에 가까워질 수는 없습니다.** 경험을 채우면 오를 여지가 크다는 신호예요.

**중간값 예시** — 숫자 60% / 경험 70% → **3.5 : 6.5** (계단이 아니라 연속적으로 움직임)

## 3. 화면별 설명 문구

### CAS 점수

> **내 CAS 점수  620 / 1000**
> 숫자 스펙 400점 + 경험 스펙 600점으로 이루어져 있어요.
> 합격한 선배들의 평균과 같으면 약 80%를 받고, 평균보다 확실히 앞서면 만점에 가까워집니다.

### 백분위·등급

> **같은 학과·희망 직무 선배들 사이에서 내 위치**
> 나와 같은 길을 준비한 선배들의 점수를 낮은 순으로 줄 세웠을 때, 내가 어디쯤 있는지를 표시한 거예요. "상위 12%"는 100명 중 12등쯤이라는 뜻입니다.

※ 선배가 **5명 미만이면 백분위를 숨깁니다.** 3명 중 2등을 "상위 33%"로 보여주는 건 정보가 아니라 착시이기 때문입니다.

### 직무역량 레이더

> **직무역량 레이더**
> 바깥쪽 도형은 **이 직무에 합격한 선배들이 갖춘 수준**, 안쪽 색칠된 도형은 **내가 지금 채운 수준**이에요. 안쪽이 바깥쪽에 가까울수록 준비가 잘 된 거고, 움푹 들어간 축이 지금 부족한 부분입니다.

### 스펙 비교

> **숫자 스펙 — 학점·어학·자격증**
> 점수나 개수로 딱 떨어지는 스펙이에요. 세로 선이 선배 평균, 색 막대가 나예요 — 막대가 선을 넘으면 평균 이상입니다.

> **경험 스펙 — 인턴·공모전·대외활동**
> 숫자로 표현하기 어려운 경험이에요. 몇 번 했는지를 선배 평균과 비교합니다.

### 부족한 항목

> **목표까지 남은 것**
> 합격한 선배들은 대부분 갖췄는데 나에게는 없는 것들이에요. 위에 있을수록 먼저 채우는 게 효율이 좋습니다.

## 4. 제품 안에서 AI가 하는 일

### 하는 일 — 딱 하나

**"학생이 자유롭게 쓴 글"을 "폼 항목"으로 바꾸는 것.**

스펙 입력 폼의 '**AI로 한 번에 입력**' 패널에서만 동작합니다.

```
입력:  카카오 마케팅 인턴 6개월 팀원으로 참여해 캠페인 CTR 개선.
       학점 3.8/4.5, 토익 875

출력:  활동 → type=인턴십 · duration=3개월~6개월 · role=팀원 · outcome=성과 있음
       정량 → gpa=3.8 · gpaMax=4.5 · toeic=875
```

원래는 드롭다운 10여 개를 하나씩 골라야 하는 걸, 글 한 번 붙여넣으면 자동으로 채워주는 **입력 도우미**입니다.

### 하지 않는 일

| 기능 | 담당 |
|---|---|
| CAS 점수 계산 (숫자 400 / 경험 600) | `cas.js` — 규칙 |
| 정량:정성 비중 (4:6 ↔ 3:7 ↔ 5:5) | `cas.js` — 규칙 |
| 백분위 · 등급 | `cas-hero.js` — 규칙 |
| 스펙 비교 막대 | `cas-compare.js` — 규칙 |
| 직무역량 레이더 | `cas-radar.js` — 규칙 |
| 회사명 → 기업규모 판정 | `company-classify.js` — 공식 명단 조회 |

**점수와 관련된 건 하나도 AI가 하지 않습니다.**

### 왜 이렇게 나눴나

- "카카오 인턴 6개월"을 읽고 `인턴십/3~6개월`로 바꾸는 일 → 표현이 무한히 다양해 규칙으로 불가능. **AI만 할 수 있음**
- `100 × 1.2 × 1.3 × 1.2`를 계산하는 일 → 답이 하나로 정해져 있음. **AI를 쓰면 오히려 틀림**

실제로 8B 모델은 같은 입력에 총점을 595 / 360으로 다르게 냈고, 근거에는 "187.2점"이라 써놓고 필드에는 100을 넣기도 했습니다.

### 안전장치 3겹

1. **`coerceActivity()`** — AI가 목록에 없는 값을 내면 `cas.js` 유효 목록 기준으로 교정
2. **`rescore()`** — AI가 매긴 활동 점수는 버리고 `CAS.scoreActivity()`로 재계산
3. **`deterministicTotal`** — 총점도 규칙 엔진 값을 화면에 표시

채점 루브릭은 `cas.js` 상수에서 읽어 프롬프트에 주입합니다. 배점을 바꾸면 AI 프롬프트도 자동으로 따라가므로 **기준이 두 벌로 갈라지지 않습니다.**

### 어떤 AI를 쓰나

- **로컬 Ollama `qwen3:8b`** (기본) — API 키·요금·외부 전송 없음. 학생 스펙이 PC 밖으로 나가지 않음
- **Groq** (`CAS_AI_PROVIDER=groq`) — 배포용. Ollama는 localhost 전제라 배포 시 전부 503

### 현재 한계

- **속도**: 요청당 약 1분 (이 PC는 iGPU라 사실상 CPU 추론)
- **줄글에 취약**: 한 문단으로 쓰면 활동 3개 중 1개만 잡습니다. **줄 단위로 나눠 쓰면 정상**

  권장 입력 형식:
  ```
  학점: 3.8 / 4.5
  어학: 토익 875
  자격증: 정보처리기사

  대표활동1) 카카오 마케팅 인턴 / 6개월 / 팀원 / 캠페인 CTR 개선
  대표활동2) 교내 창업동아리 / 1년 / 회장
  대표활동3) 전국 대학생 광고공모전 / 3개월 / 팀장 / 장려상
  ```
- **AI 실패 = 기능 실패 아님**: AI가 꺼져 있어도 직접 폼을 채우면 점수는 똑같이 나옵니다. AI는 편의 기능이지 필수 경로가 아닙니다

## 5. 기업규모 자동분류

회사명을 입력하면 **대기업 / 중견기업 / 중소기업 / 공기업** 4가지로 자동 판정합니다.
외부 API를 매번 부르지 않고, 공식 명단을 미리 받아 `data/*.json`에 캐시해 두고 조회합니다.

| 소스 | 판정 | 건수 | 상태 |
|---|---|---|---|
| 공정거래위원회 대규모기업집단 | 대기업 | 3,539 | ✅ |
| 재정경제부 공공기관 지정현황 | 공기업 | 355 | ✅ |
| 행안부 지방공기업·지방출자출연기관 | 공기업 | 1,312 | ✅ |
| 고용24(워크넷) 기업구분 | 중견기업 | — | ❌ 미완 |

- 지방공기업 2종은 오픈API가 없어 **CSV를 받아 `backend/data/raw/`에 두고** `node scripts/fetch-local-public-orgs.js`로 갱신합니다
- 지방출자출연기관(재단·진흥원)도 **공기업 한 칸**으로 묶습니다 — 취업 준비 관점에서 공공부문 채용으로 보는 게 유용하다는 판단
- **중견기업만 미완**입니다. data.go.kr에 중견기업 명단 데이터셋이 없어(집계 통계만 있음) Work24 API가 사실상 유일한 소스인데, 요청 URL이 로그인 뒤 개발명세서에 있어 확보하지 못했습니다

## 부록 — 실행 방법

```bash
cd Downloads/careerly/backend
npm start                  # http://localhost:3000
```

**반드시 `http://localhost:3000`으로 접속해야 합니다.** HTML 파일을 직접 열면(`file://`)
API 호출이 상대 경로라 전부 `Failed to fetch`가 납니다.

기업분류 명단 갱신:
```bash
node scripts/fetch-ftc-groups.js          # 공정위 대기업 (최신 지정년월 자동 탐색)
node scripts/fetch-public-orgs.js         # 공공기관
node scripts/fetch-local-public-orgs.js   # 지방공기업 (data/raw 의 CSV 사용)
```

테스트:
```bash
node test/cas.test.js      # 41개
```
